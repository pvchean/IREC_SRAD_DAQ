# MTP Deviation Log

Each row records a change from the old behaviour. Date: 2026-11-11. Branch: `mtp-usb-mode`.

| Date | What changed against the old behaviour | Why | Effect |
|---|---|---|---|
| 2026-11-11 | MODE2 low was "files mode, not used yet" in `src/board.h` and README. Now the `daq_mtp` build uses MODE2 low as files mode. | Files mode (USB MTP, read-only) is in development. | Only the `daq_mtp` build changes. The `daq` build ignores MODE2 as before. |
| 2026-11-11 | `src/cmd.c` and `src/stream.c` call `cio_*` functions instead of direct `usb_serial_jtag_*` calls. | One transport layer lets files mode swap the console backend. | Same bytes on USB Serial/JTAG in the `daq` build. `cmd_start()` installs the driver through `cio_init()`. |
| 2026-11-11 | In the `daq_mtp` build, `REC ON` is refused. MODE1 high does not auto-record. | No data may be written while the NAND is read-only for MTP. | `REC ON` replies `REC:ERR recording is disabled in this build (daq_mtp)`. No file is saved. |
| 2026-11-11 | Files mode runs no sensors, no chain, no WiFi and no recording. | Files mode only reads the store. | The board only serves files. Sensor and radio code do not start. |
| 2026-11-11 | The `daq_mtp` build sets the task watchdog to 8 s with panic (`CONFIG_ESP_TASK_WDT_PANIC=y`, `CONFIG_ESP_TASK_WDT_TIMEOUT_S=8`) and `CONFIG_ESP_SYSTEM_PANIC_SILENT_REBOOT=y`, in both modes. The `daq` build keeps 5 s and no panic. | A hung USB stack must reset the chip with no human (Spike_Report.md MTP-P-10). A panic print to a dead console could block the reset. | In `daq_mtp` serial mode a watchdog or panic reset is silent (no backtrace on the console). `daq` is unchanged. |
| 2026-11-11 | `daq_mtp` files mode has the CDC commands `DL`, `REBOOT`, `LEAVE`, `LOG` and (test only) `HANG`. They are read by the USB code itself, not by the `cmd` task. | The way back from files mode must work when the `cmd` task is busy (Merge_Report.md MTP-M-5). | Only in `daq_mtp`. The `daq` build has none of them. |
| 2026-11-11 | New folder `mtp_usb/` (esp_tinyusb fork), new lock file `dependencies.lock.daq_mtp`, new env `daq_mtp_force`. The top `CMakeLists.txt` has a block for `-DDAQ_MTP_USB=ON`. | The USB stack must not touch the other envs (Merge_Report.md MTP-M-2). | `daq` image: the same loadable sections and symbols as before (only the build date field differs). |
| 2026-11-11 | Host test fixes in the esp_tinyusb fork (`mtp_usb/fork/esp_tinyusb`), all marked `FORK (MTP-H)` in the source. Details and file:line in `HostTest_Report.md` MTP-H-4. (a) Every operation except GetDeviceInfo and OpenSession returns SessionNotOpen (0x2003) with no open session. (b) OpenSession with SessionID 0 returns InvalidParameter; SessionAlreadyOpen carries the open SessionID. (c) GetObjectHandles: parent 0xFFFFFFFF now lists only the root objects, parent 0 lists all objects (upstream had them swapped). (d) ObjectInfo and object properties: ParentObject of a root object is 0 (was 0xFFFFFFFF); ThumbFormat is 0 (was 0x3000); ObjectInfo has DateCreated and DateModified; the ProtectionStatus property is read-only (1) as in ObjectInfo; ObjectFileName is Get only. (e) GetObjectPropList accepts handle 0 (the root). (f) DeviceInfo lists one event, CancelTransaction (0x4001), not one event with code 0x0000. | The host test (`tools/mtp_hosttest`) ran the real handlers for the first time and compared every dataset with PIMA 15740 and MTP 1.1. | Only `daq_mtp*` builds. Not tested on a real host (Windows, macOS, libmtp). Change (c) is the one most likely to matter: libmtp and Windows ask for the root with 0xFFFFFFFF. |
| 2026-11-11 | Refused write operations (SendObjectInfo, SendObject, SetObjectPropValue, AndroidSendPartialObject, and the not advertised SetDevicePropValue, SetObjectPropList, SendObjectPropList, SetObjectReferences) now read and drop the host data phase, then answer with the error (0x200E, 0x200F or 0x2005). Before, the device answered in the command phase and never armed the OUT endpoint. `mtp_device.c` (TinyUSB class driver, P1 patch file) takes the length of an OUT data phase from the header of its first packet. An error in the middle of a read (store error, cancel) now sends a valid header-only response. | The old code deadlocked a host that writes the data container before it reads the response (libmtp). The old mid-transfer response sent file bytes as a "response". | Only `daq_mtp*` builds. Nothing is ever written. |
| 2026-11-11 | Static review fixes, marked `REVIEW (MTP-V)` (Review_UsbFiles.md). (a) MTP-V-4: TinyUSB task stack 6144 -> 8192 bytes (`usb_files.c`). (b) MTP-V-5: in files mode `SDLS` and `CHUNK SD` ask for the SD card through `mtp_vfs_sd_present()`, under the shim lock (`cmd.c`, `mtp_vfs.c`). (c) MTP-V-6: a refresh no longer frees the open file slots of the shim; old handles still fail with EIO, and `v_open()` reuses an old slot only when no slot is free. (d) MTP-V-9: the CDC command `LOG` ends with a `DIAG` line (free heap, minimum free heap, free stack of the tasks TinyUSB, mtp_vfs, cmd, main, led) before `END`. (e) MTP-V-10: a failed CDC init drops D+ and restarts, in place of `abort()`. | Stack margin, one caller at a time on the SD store, no wrong close of a reused fd, measure the margins on hardware, no stale device after a failed init. | Only `daq_mtp*` builds (`cmd.c` change is under `DAQ_MTP_USB`). `daq` unchanged. Host test 8427/8427 pass. Not tested on hardware. |
| 2026-11-11 | Code polish, marked `POLISH (MTP-R)`. (a) Main task stack 3584 -> 5632 bytes (+2 KB): `CONFIG_ESP_MAIN_TASK_STACK_SIZE` in `mtp_usb/daq_mtp.defaults` (measured free stack of `main` was 1376 B; heap minimum was about 49 KB). (b) `usb_stack_start()` in `src/usb_files.c` sets the log level of the 8 MTP/TinyUSB tags (`tinyusb_mtp_transport`, `_ops`, `_read`, `_xfer`, `_write`, `_store`, `_prop`, `_codec`) to WARN at run time. The per-transaction `MTP trace` INFO lines go away. Errors and warnings stay. (c) The CDC command `HANG` exists only with `-DUSB_FILES_TEST_CMDS=1`. Only env `daq_mtp_force` sets it (`platformio.ini`). Closes MTP-V-12. | Stack margin; the LOG ring (6144 B) filled in a few MTP reads; one stray `HANG` must not reset a normal image. | Only `daq_mtp*`. `daq` unchanged. FLASHED later the same day (see Hardware_Report.md MTP-HW-7): main stack free 3408 B, trace lines gone. Builds `daq_mtp_force`, `daq_mtp`, `daq` clean; host test 8427/8427; `HANG` string is in the `daq_mtp_force` image only. Tested on hardware (INFO clean, DIAG read, KDE copy). |
| 2026-11-12 | Files mode accepts `MATLAB PING` and `STREAM OFF`, marked `REVIEW (MTP-A)`. `MATLAB PING` prints the same banner as in serial mode but starts no stream and no task. `STREAM OFF` prints `STREAM:OFF` and changes nothing. The allowlist is now the pure function `files_mode_classify()` in the new `src/files_mode_cmd.h`; `files_mode_cmd()` in `cmd.c` uses it. Host test `tools/mtp_hosttest/cmdtest.c` (80 checks) runs from `run.sh`. | MTP-HW-10.3: the MATLAB apps connect with `MATLAB PING` and wait for `DAQBOARD V1`, and the file download waits for `STREAM:OFF`. Both were refused in files mode. | Only the files-mode branch changes (`files_mode_active()` true). Serial mode: unchanged. Nothing writes the NAND, NVS or the calibration. Builds `daq_mtp`, `daq_mtp_force`, `daq` clean. NOT flashed. NOT tested with the real MATLAB app (UNVERIFIED). |
| 2026-11-12 | Marked `REVIEW (MTP-C)`. (a) `src/usb_files.c`: three more CDC test commands, only with `-DUSB_FILES_TEST_CMDS=1` (env `daq_mtp_force`): `ABORT` (`abort()`), `CRASH` (write through a null pointer), `INTWDT` (interrupts off in a loop: interrupt watchdog). The strings are absent from the `daq_mtp` image. (b) The per-tag WARN levels of the 8 MTP trace tags are set again by the new `usb_files_log_quiet()` after the CHUNK command (`cmd.c`), because `esp_log_level_set("*", ESP_LOG_INFO)` at the end of CHUNK removed them (MTP-HW-13 problem 7). | (a) Crash recovery of panic types other than the task watchdog was not tested (MTP-HW-8.4). (b) The first serial download brought back the INFO trace lines, which filled the 6 KB LOG ring. | (a) Only `daq_mtp_force`. (b) Only `daq_mtp*`: the `cmd.c` call is under `DAQ_MTP_USB`. `daq` unchanged. Host test 8427/8427. |
